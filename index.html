What these add-ons do

These are the major pieces added on top of stock Spire so it can be the single local emulator tool.

PEQ Editors hub

Every PHP editor tab from peqphpeditor, mapped onto local pages. Dedicated tools stay as full pages. The rest open a table editor against the same peq tables.

Items + icons

Search by name, class, race, deity, slot, and flags. Class, race, and deity chips use EQ icons. Result tables and cards show item icons and wearable class icons.

Evolving items

Targeted tables in order: define the chain in items_evolving_details, then match item columns. Type 4 is zone-kill (zone IDs in subtype, kill count in required amount).

Inventory editor

Paperdoll, bags, bank, shared bank, and parcels with item icons. Click a bag to open it, target an empty slot, place or remove items.

Zone 2D + 3D

2D map with spawn markers and placement edit. 3D Atlas loads the Lantern zone mesh, NPCs, and client scenery. Orbit, zoom, wireframe, and lighting toggles.

Server files + privacy

Point Spire at a quests folder (or HTTP host) and edit perl/lua in place. Hide private details blurs names, addresses, keys, passwords, hosts, and paths for streams.

Content Factory

Census a live zone, cherry-pick trash vs named, mint item kits and dual loot tables, clone NPC spell sets into the 50000–65535 band, then run one pipeline that writes clones at 800000+ instead of editing vanilla PEQ. Lint, draft, pawn, give, probe, undo.

Tier Factory

Named recipes with trash / boss / raid numbers plus a gear kit. Stamp copies that kit onto many zones. Ladder steps each zone by the multiplier and mints a new item ID range so T2 is not wearing T1 loot.

Content Factory

Zone census + cherry-pick

Load a zone’s real spawn data: role, HP, pops, faction, loot table, NPC spell set, casts, and merchant. Checkboxes exclude NPCs from writes. Neighbors, ground spawns, and forage counts sit on the same page. Default target is trash; merchants are skipped.

Content Factory

Reserved ID board

Next free ID is max(floor, max+1) for items, spells, NPC types, loot, and merchant lists. Custom gear starts at 800000. NPC-castable spell clones stay in the 50000–65535 band so they fit the npc_spells_entries.spellid column.

Content Factory

Item kit studio

An 18×16 class/slot grid. Each cell is a source item ID. Import fills from a live zone’s loot. Preview clones and scales; write mints new item rows in the reserved range and saves the recipe for Tier Factory.

Content Factory

Dual loot composer

Trash and named tables attach separately. Leave named empty if you only want trash drops. Use last kit items, set cash and probability, then preview the attach list before writing lootdrop rows.

Content Factory

One pipeline run

Spells → kit → NPC clones → trash/named loot → dual spell sets → merchant attach → client export → reload → probe. Clone NPCs at 800000+ instead of editing vanilla rows. Lint and a post-write probe run before anything is treated as done.

Content Factory

NPC spell-set factory

Clone an npc_spells list and its entries. Spell IDs stay at or below 65535 so they fit the entry column. Attach the new set to cherry-picked NPCs or a zone list. Search existing lists (Default Magician, Default Shaman List) as the source.

Content Factory

Spell-set editor

Load an npc_spells list, edit min/max level, type, mana, recast, and priority, then save as a new 800000+ list or replace the source. Search spells by name to add entries.

Content Factory

Test pawn + give

Spawn a SPIRE_TEST_ NPC at the zone safe point, or put minted items on a character inventory. Preview writes first. Probe last plan / zone checks that the client export and zone JSON actually contain the new IDs.

Tier Factory

Named recipes + stamp / ladder

A recipe is the tier: trash / boss / raid numbers plus a gear kit. Stamp copies that kit onto many zones. Ladder steps each zone up by the multiplier and mints a new item ID range so T2 is not wearing T1 loot. Mint the kit itself in Content Factory.

Zone Controller files — where they go

Spire is only the editor. The zone process runs quests/global/zone_controller.pl. This pack is that real script (including the 2-second Spire Apply poll) plus blank mob / loot / item templates. No live item or NPC kits.

Why the controller exists

Stock EQEmu stores every NPC in PEQ (npc_types, spawn2, loot tables). Changing Blackburrow trash HP or a named drop usually means editing those rows. That mutates vanilla data, is hard to revert, and already-popped NPCs keep old memory until a full repop. The controller is a global quest NPC (id 2000986, name zone_controller) that EQEmu auto-spawns. It leaves those spawn rows alone and overlays live entities from JSON.

Overlay, do not rewrite vanilla

On spawn it loads ultimatedata/<zoneid>/{mob,loot,item}.json. Missing files are copied from the blank templates. -1 in basedata means leave the vanilla stat. You can scale a zone, then delete the kit and the stock PEQ rows are still there.

Classify every spawn

Each NPC is trash, a named custom (boss / raid), ignore, or depop. Ignore skips pets, merchants, and the controller itself so they are not scaled. Depop removes placeholders you do not want in the zone. Custom names override the trash defaults.

Buff and loot in live memory

SET_MOB_BUFFS writes level, HP, size, cash, and other ModifyNPCStat keys onto the spawned NPC, then heals it. SET_MOB_LOOT clears the corpse list and rolls JSON tables onto it. That is how you test a drop table without rewriting lootdrop first.

Catch respawns

New pops signal the controller so a fresh spawn is buffed immediately. Reconcile timers at 1s, 5s, and 30s after boot, then every 1s with players in zone (30s when empty), walk the NPC list and apply anything still pending. A missed signal does not leave a vanilla-stat mob sitting next to scaled trash.

Inspect in-game

A GM hail (or !zc / #zc) opens the same menu: mob lists, ignore / depop, loot tables, per-type stats, and a diagnostics dump (signals, reconcile counts, apply ok / fail). That is for standing in the zone and asking “what did the script just do to this NPC?”

Apply from Spire without hailing

Every 2 seconds PROCESS_SPIRE_COMMANDS picks up _spire_commands/<zoneid>.json and runs the same tokens as hail: refreshzonedata, rebuffzone, applyallchanges, repop / depop. It writes a .result.json and a GM say. Files on disk are not live until that reload.

For emu development that split is the point. Content Factory mints new PEQ rows at 800000+ (items, clones, spell sets). The controller is the runtime that uses those IDs on a popped zone without a SQL dump or a zone reboot for every HP tweak. Builder / Tier Factory stamp the same JSON kit onto many zone ids. Preview in Spire, write files, Apply — iterate a zone the way you iterate a quest script, instead of hand-editing vanilla npc_types.

This is why the pack ships the live zone_controller.pl, not a stub. Spire’s Zone Controller page only writes JSON. Without this script in quests/global/, Apply has nothing to poll and the zone keeps stock stats.

Requirements

The zone process runs Perl. Dropping the files in is not enough if that runtime is missing.

Perl runtime

EQEmu zone.exe must already load Perl quests. On Windows that is usually Strawberry Perl on PATH. The zone working directory must be the folder that contains eqemu_config.json so MySQL.pl can open it.

Perl modules

instance_tools.pl needs the CPAN JSON package (not only core JSON::PP). Name lookups need DBI and DBD::mysql. JSON::PP, File::Copy, and File::Path are core.

perl -MJSON -MJSON::PP -MDBI -MDBD::mysql -e "print qq{ok\n}"

Database + NPC

eqemu_config.json → server.database must work. Insert NPC 2000986 named zone_controller (SQL is in the pack). EQEmu auto-spawns that name; most zones do not need a spawn2 row.

If the Perl check fails on Strawberry: cpan JSON then cpan DBI then cpan DBD::mysql. quests/ must sit next to zone.exe, or set EQEMU_QUEST_ROOT. Full list: REQUIREMENTS.md.

Sage, Lantern, and 2D maps

Do not put these in the Zone Controller zip. They are client-side tools and use the recipient’s own EverQuest files.

2D zone map

Comes with Spire. On first launch the exe downloads eq-asset-preview (map lines, icons, NPC sprites). Internet once. No extra pack.

Sage

The Sage page loads EQ Sage from the web (eqsage.vercel.app through Spire). The user clicks Connect EQ folder on their own client directory. Sage writes an eqsage/ cache next to those files. Chrome + their EQ install. You cannot ship someone else’s client.

Lantern / Atlas 3D

Atlas reads .glb meshes from a LanternExtractor Exports folder (<zone>/Zone/<zone>.glb). Point Spire at it with SPIRE_LANTERN_ROOT, or leave Exports in Downloads / Desktop / Documents under the default LanternExtractor path. Each person extracts their own client. Those meshes are large and not part of this pack.

New server

Copy the quests/ tree next to eqemu_config.json. Run the SQL. Pop a zone. Hail the auto-spawned controller or click Apply in Spire. First init copies the blank templates into ultimatedata/<zoneid>/.

  1. Unzip so quests/global/zone_controller.pl sits next to your other global quests.
  2. From the server folder run perl -MJSON -MJSON::PP -MDBI -MDBD::mysql -e "print qq{ok\n}". If that fails, install Strawberry Perl and cpan JSON DBI DBD::mysql.
  3. Run npc_types_zone_controller.sql if you do not already have NPC 2000986 named zone_controller.
  4. Point Spire at that same server folder (or set SPIRE_QUESTS_ROOT).
  5. Pop the zone. Apply from Spire writes _spire_commands/<zoneid>.json; the controller picks it up within about 2 seconds.
  6. Optional: merge snippets/global_player.zc-snippet.pl for cross-zone !initdata <zoneid>.

Blank templates use -1 for every basedata stat (leave vanilla NPCs alone) and empty loot / item / custom lists. Fill those in Spire. Do not ship someone else’s item or NPC data unless you mean to. Full notes: zone-controller/README.md.
